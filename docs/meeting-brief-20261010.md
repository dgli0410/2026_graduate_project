# 졸업작품 팀 회의 — 내가 맡은 부분 설명 준비

나는 대학 졸업작품 팀(4명)에서 **평가셋 구축과 성능 측정**을 맡고 있다. 오늘 회의에서
내 작업을 설명해야 한다. 아래가 지금까지의 상황이다. **내가 뭘 어떻게 설명하면 좋을지,
팀원이 물어볼 만한 질문과 그 답을 같이 정리해 달라.**

## 1. 프로젝트가 뭔가

유튜브 쇼츠를 "저장"하면 크롬 확장이 영상을 재생하며 **0.5초마다 화면을 캡처**하고
**오디오를 녹음**해 서버로 보낸다. 서버가 분석해 **4초 단위 "장면 카드"** 로 쪼갠다.

장면 카드 하나에는 네 가지가 들어간다.

| 항목 | 무엇 | 만드는 것 |
| --- | --- | --- |
| `asr_text` | 음성 받아적기 | faster-whisper (로컬) |
| `ocr_text` | 화면 자막 | EasyOCR (로컬) |
| `caption` | 장면 설명 | Gemini API |
| 좌표 | 검색용 벡터 | BGE-M3(글) + SigLIP2(그림), 둘 다 로컬 |

나중에 **"마늘은 언제 넣어?"** 라고 물으면 관련 장면을 찾아 **그 초로 영상을 이동**시킨다.
요리 쇼츠 도메인이다. 현재 영상 18개, 장면 카드 203개가 저장돼 있다.

## 2. 검색이 어떻게 동작하나 (평가 대상)

질문이 들어오면 **세 신호**를 가중합해 장면을 정렬한다.

| 신호 | 무엇 |
| --- | --- |
| **글 좌표** | 장면 카드 텍스트와 질문의 의미 유사도 (BGE-M3) |
| **정확한 단어** | 질문 단어가 실제로 들어 있는지 (IDF 가중) |
| **그림 좌표** | 프레임과 질문의 유사도 (SigLIP2) |

가중치는 질문 성격(수량형/시각형/일반)에 따라 바뀌는데, **9개 숫자가 전부 사람이 감으로
써 둔 상수**다. 이걸 데이터로 정하는 게 평가셋의 목적이다.

## 3. 멘토 자문 (9/18, 현업 전문가 서면)

평가 설계에 대해 이렇게 지시받았다.

1. 정답을 이진이 아닌 **등급(정확 2 / 관련 1 / 무관 0)** 으로 라벨링하고 **nDCG 를 주지표**로
2. 시점 정확도는 **비대칭 허용 오차** (예: 이전 5초, 이후 2초). 사용자는 목표보다 앞서
   시작하는 건 감수해도 지나쳐 시작하는 건 감수하지 못한다
3. **질문 유형별**(재료·분량 / 순서·타이밍 / 시각적 상태)로 성능을 분리해 보고할 것.
   전체 평균 하나보다 유형 간 차이가 더 유용하다
4. **비교 기준선**을 둘 것. 절대 수치보다 기준선 대비 개선폭이 설득력 있다
5. **편향 방지** — 개발팀이 질문과 정답을 모두 만들면 시스템이 잘 푸는 질문으로 기운다.
   2인 이상 독립 라벨링 후 일치도를 확인하**거나** 질문 작성만이라도 팀 외부에 의뢰할 것
6. 근거가 불충분하면 답을 생성하지 말고 **"관련 장면 없음"** 을 안내할 것

## 4. 내가 한 것

### 평가셋 (완료)

- **질문 64개** — 팀원 4명이 각자 **외부 지인**에게 받아왔다 (자문 5번의 "또는" 조건 충족)
- **정답 라벨 113줄** — 전부 팀원이 직접 작성. 2점 49줄 / 1점 51줄 / "정답 없음" 13줄
- 정답을 **세그먼트 번호가 아니라 시간 구간(초)** 으로 적었다. 나중에 4초 카드를 의미
  단위로 병합해도(자문 1번) 평가셋을 다시 만들 필요가 없다
- **"답이 없는 질문" 13개(20%)** 를 일부러 섞었다. 자문 6번을 시험하려면 필요하다

### 평가 스크립트 (완료)

nDCG@5 주지표, Recall@K, mAP, 1위 적중률, 비대칭 허용 오차(이전 5초/이후 2초),
질문 유형별 분리, 기준선 2종.

만들면서 버그를 하나 잡았다 — 허용 오차가 이전 5초로 넓어서 **맞닿은 4초 카드 여러 장이
같은 정답에 동시에 걸렸고**, 매번 득점시켜 nDCG 가 1.15 까지 나왔다(1을 넘을 수 없는 값).
정답 구간 하나는 한 번만 득점하도록 고쳤다.

### 버그 3개 발견·수정 (완료)

백엔드를 로컬 모델로 바꾸는 과정에서 찾았다. **셋 다 에러 없이 조용히 틀린 값을 내고
있었다.** 서버는 정상으로 보이고 영상도 "완료"로 끝났다.

| # | 증상 | 원인 |
| --- | --- | --- |
| 1 | 분석이 전부 실패 | `.env` 의 **빈 값 뒤 인라인 주석을 값으로 읽음**. `SIGLIP_ADAPTER=  # 설명...` 에서 주석 전체가 값이 되어 없는 폴더를 찾다가 죽음. 값이 **있는** 줄은 정상이라 눈에 안 띔 |
| 2 | 좌표 저장 실패 | 글 좌표를 768차원에서 1024차원으로 바꿨는데 **창고(Qdrant)가 768 그대로**. 삭제 명령이 메타데이터만 바꾸고 실제 저장 파일을 남겼다 |
| 3 | **자막이 통째로 빔** | EasyOCR 에 경로를 넘기면 내부에서 OpenCV 를 쓰는데, **OpenCV 는 윈도우에서 한글 경로를 못 연다.** 프로젝트 폴더 이름에 한글이 있어 전 프레임 실패 |

3번이 제일 지독했다. **OCR 이 비면 Gemini 가 읽은 글자가 대신 채워져서** 겉보기로는
완전히 정상이었다. 다른 팀원이 넣어둔 단계별 상태 기록이 없었으면 끝까지 몰랐을 것이다.

수정 후 **OCR 성공 0/18 → 18/18**, 자막이 들어간 장면 **94%**.

1번과 3번은 **다른 팀원도 그대로 겪는다** — 1번은 설정 파일을 복사해 쓰는 전원,
3번은 경로에 한글이 있는 전원.

## 5. 첫 측정 결과

질문 60개 중 48개 측정 (+ 정답 없음 12개는 따로 집계).

| | nDCG@5 | Recall@5 | 1위적중 |
| --- | ---: | ---: | ---: |
| 기준선 — 음성 신호만 | 0.721 | 0.802 | 0.646 |
| **현행 시스템** | **0.747** | 0.802 | 0.708 |

### 유형별 — 세 번 측정에서 순서가 유지됐다

| 유형 | nDCG@5 | 질문 수 |
| --- | ---: | ---: |
| **시각적 상태** | **0.855** | 13 |
| 순서·타이밍 | 0.709 | 16 |
| **재료·분량** | **0.705** | 19 |

표본 크기와 색인 내용이 바뀐 세 번의 측정에서 **모두 같은 순서**였다. 시각적 상태가 가장
잘 찾히고 재료·분량이 가장 약하다. 예상과 반대다 — 시각 질문이 어려울 거라 봤다.

재료·분량이 약한 건 **자막 의존도가 높기 때문**으로 보인다. EasyOCR 이 `1큰술` 을
`1근술`, `350ml` 를 `35Oml` 로 읽는 오인식이 기록에 남아 있고, 단어 매칭에서
`1큰술` 질의가 `1근술` 자막에 걸리지 않는다.

### 자문 6번 (관련 장면 없음) — 현재 0/12

**정답이 없는 질문 12개 전부에서 결과를 내놓는다** (평균 1위 점수 0.71).
점수 정규화가 1등을 항상 1.0 으로 만들기 때문에 "자신 없음"을 표현할 수 없다.
→ 임계값 도입 전후를 비교할 **기준선이 생겼다.**

## 6. 아직 못 쓰는 것 (정직하게 말해야 하는 부분)

| 항목 | 문제 |
| --- | --- |
| **지금 숫자는 확정이 아니다** | Gemini 일일 할당량(모델당 20회)을 다 써서 **5개 영상에 장면 설명이 빠졌다**(설명 채움률 55%). 그 5개에 질문이 20개 붙어 있다. 할당량 복구 후 다시 재야 한다 |
| **기준선 하나가 무의미** | "제목·설명만으로 검색" 기준선이 현행과 **소수점까지 동일**하다. 영상 **안에서만** 검색하면 제목이 모든 카드에 같아 재정렬이 일어나지 않는다. 영상 내 검색에서 성립하는 기준선으로 바꿔야 한다 |
| **라벨러 일치도(κ) 없음** | 담당을 **영상별**로 나눠서 같은 질문을 두 사람이 라벨링한 경우가 0건이다. 질문을 외부에 의뢰했으므로 자문 5번의 "또는" 조건은 충족하지만, κ 는 낼 수 없다 |
| **질문 4개 사용 불가** | 팀원 한 명이 담당 영상 대신 본인 테스트 영상으로 질문을 만들었다. 그 영상이 공용 색인에 없다 |
| **표본이 얇다** | 유형당 13~19개. 유형 간 차이를 말하기엔 적다. 특히 시각적 상태가 13개뿐 |

## 7. 회의에서 정해야 할 것

1. **캡션 5개 채우기** — 할당량 복구 후 그 5개만 다시 분석 (내가 함)
2. **팀원 한 명의 질문 4개** — 본인 테스트 영상이 공용 색인의 김치찜과 같은 영상인지 확인.
   같으면 1분이면 살아나고, 다르면 질문을 다시 만들어야 한다
3. **시각적 상태 질문 보강** — 각자 2~3개씩. 이 유형이 우리 프로젝트의 핵심인데 가장 적다
4. **그 다음 개선 순서** — 임계값 → 세그먼트 병합 → 가중치 재설계. 각각 재측정
