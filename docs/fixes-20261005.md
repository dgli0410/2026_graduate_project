## 1. 음성이 모든 영상에서 빈 값이었다 ★

**증상** — 영상 4개 24개 카드의 `asr_text` 가 **전부 빈 문자열**. 로그에는 아무것도 안 찍힘.

**PyAV 15 부터 그 인자가 없어졌습니다.** 설치된 PyAV 는 19.0.1.


오디오를 열 때마다 죽었고, 파이프라인이 예외를 삼켜 빈 결과가 됐습니다.

**수정** — `_decode_audio()` 를 추가해 PyAV 19 API 로 직접 16kHz 모노로 디코딩하고,
파일 경로 대신 **ndarray 를 넘깁니다.** faster-whisper 의 `decode_audio` 를 통째로 건너뜁니다.

## 3. 자막(OCR) 품질 — 원인 3개

**수정 전**

```
밥 한 공기 순삭할 수 있는 C다 'F60" 1' ;;} S다a 밥 한 공기 순삭할 수 있는 e3: 밥 한 공기...
J의오늘되업지? 고춧가루 1근술 쉬고 J의오늘딪업D8 교춧가루 1근술 쉬고 J의오늘되업지? 새우...
```

### ① 신뢰도를 버리고 있었다

`readtext(..., detail=0)` 이라 **점수 없이 글자만** 받았습니다. 배경 무늬에서 나온 쓰레기를
거를 방법이 없었습니다.

→ `detail=1` 로 신뢰도·위치를 받고 **0.35 미만 제거**.
0.5 로 잡으면 작은 한글 자막까지 날아갑니다(실측: `양파 반 개` · `파 1/2대` · `청고추 2개` 소실).
낮게 잡는 대신 **내용으로** 거릅니다 — 한글이 있거나, 숫자가 있고 3자 이상일 때만 통과.
로고 파편(`jc` `jic` `ral` `e3`)이 여기서 걸리고 `600ml` 은 통과합니다.

### ② 채널 워터마크가 매 프레임 읽혔다

파스타 영상의 채널 로고가 **카드마다 5회씩** 들어갔습니다. 더 나쁜 건 매번 다르게 읽혀서
(`J희오늘딪먹지8` / `J의오늘되업지` / `J희오늘딪목지8`) **단순 중복 제거로는 안 걸렸다**는 점입니다.

→ `_drop_static_overlays()`. **위치만 보면 안 됩니다** — 쇼츠 자막도 보통 같은 높이에 뜹니다.
그래서 **같은 칸에 계속 나오면서(프레임의 80% 이상) 글자까지 서로 닮은(유사도 0.5 이상)**
경우만 지웁니다. 로고는 오인식이 섞여도 서로 닮고, 자막은 내용이 바뀌어 닮지 않습니다.

### ③ 같은 자막이 8번 중복됐다

0.5초마다 1장이라 4초 카드에 같은 자막이 8장 들어옵니다. 기존 중복 제거는 **문자열이 정확히
같을 때만** 걸려서, OCR 이 매번 조금씩 다르게 읽으면(`올리브유 두르고` / `올리브유 무르고`)
전부 남았습니다.

→ `segmenter._join()` 에서 유사도 0.8 이상이면 같은 말로 봅니다.

**수정 후**

```
고춧가루 1근술 쉬고 새우 넣어 볶아 주다가 물 6OOm) 로마로 소스 2/33
```

| | 전 | 후 |
|---|---|---|
| 로고 파편 잔존 | 카드마다 5회 | **0건** |
| 자막 채움률 | 20/24 | 21/24 |
| 말 채움률 | **0/24** | **16/24** |

> **남는 한계.** `삼경살`(삼겹살) · `1근술`(1큰술) · `35Oml`(350ml) · `로마로`(토마토) 같은
> **EasyOCR 자체의 한글 오인식은 필터로 못 고칩니다.** 쇼츠 자막이 장식 폰트에 외곽선까지
> 있고 프레임이 540×960 JPEG 품질 0.75 라 작은 글자가 뭉개집니다.
> 단어 매칭에서 `1큰술` 질의가 `1근술` 자막에 안 걸리는 실패가 실제로 가능합니다.

## 4. 정답 장면의 양 옆 카드가 항상 삭제됐다 ★

**증상** — `top_k=5` 인데 카드 5개짜리 영상에서 **결과가 3개만** 나왔습니다.

**원인** — `dedup_adjacent` 의 조건이 이랬습니다.

```python
start <= 상대end + overlap  and  end >= 상대start - overlap     # overlap = 2.0
```

장면 카드는 4초씩 **맞닿아** 있습니다(`0~4`, `4~8`, `8~12`, …). 겹치는 구간이 **0초**인데도
앞뒤 2초 여유 때문에 맞닿은 카드가 전부 중복으로 걸렸습니다.

```
8~12 남김  →  4~8 삭제, 12~16 삭제  →  0~4 남김, 16~18 남김   = 관측된 3개
```

**상위 카드의 양 옆이 언제나 지워집니다.** 정답이 카드 경계에 걸치면(흔합니다) 그 옆 카드를
영영 보여줄 수 없습니다. 라벨링 허용 오차가 **이전 5초**인 것을 생각하면 평가에서 치명적입니다.

**수정** — 겹친 **길이**를 재서 `overlap` 초 이상일 때만 중복으로 봅니다.
맞닿은 카드는 겹침이 0 이라 둘 다 남습니다. 나중에 세그먼트를 의미 단위로 병합해(멘토 자문 1)
실제로 겹치는 구간이 생기면 그때 의도대로 동작합니다.

## 5. 단어 점수가 상시로 깎였다

**증상** — `"두부 깍둑썰기 하는 장면"` 에서 `두부` 가 캡션에 있는데도 단어 점수 **0.251**.

**원인** — IDF 가 **코퍼스에 한 번도 안 나오는 단어에 최대 가중치**를 주고 있었습니다.

```
두부(있음) 1.83  +  깍둑썰기(없음) 2.53  +  장면(없음) 2.53   →  1.83 / 6.89 = 0.27
```

없는 단어는 **어느 후보도 맞힐 수 없는데** 분모만 키웁니다. 특히 `장면` 은 질의에 거의 항상
들어가지만 어느 카드에도 안 적혀 있어서, **모든 검색의 단어 점수를 상시로 깎고 있었습니다.**

**수정** — `df == 0` 인 단어는 제외합니다(증거가 될 수 없음). 위 예시가 **1.000** 이 됩니다.

> `lexical_score` 는 min-max 정규화를 거치지 않고 그대로 가중합에 들어가므로, 절대값이
> 순위에 직접 영향을 줍니다.

## 6. 저장한 영상 제목이 전부 같았다

**증상** — 영상 4개를 저장했는데 제목이 모두 `라면 보다 쉬운 파스타 만들기`.
**`video_id` 는 전부 정상**이라 알아채기 어려웠습니다.

**원인** — 유튜브가 쇼츠 DOM 을 바꿔 `ytd-reel-video-renderer[is-active]` 가 안 잡히고,
`#shorts-player` 나 `document` 로 떨어졌습니다. 쇼츠는 여러 개가 DOM 에 동시에 있으므로
`querySelector` 가 **문서 전체의 첫 번째 제목**을 집었습니다. `video_id` 는 URL 에서 읽어
멀쩡했습니다.

**수정** — 화면에 **실제로 보이는** `video` 요소에서 컨테이너를 거슬러 올라가고,
못 찾으면 `document.title` 로 폴백합니다(쇼츠를 넘기면 같이 바뀌므로 믿을 만합니다).

**이미 저장된 제목**은 유튜브 oEmbed 로 3개를 교정했습니다.
`pV-55c-Ri4w` 는 HTTP 401(비공개/퍼가기 차단)이라 자동 교정이 안 됩니다.

> ⚠ 제목은 Qdrant 페이로드와 **임베딩되는 텍스트(`search_text`)에도** 들어갑니다.
> SQLite 만 고치면 부족하고 재색인이 필요합니다.

## 7. 재색인 도구가 SigLIP 벡터를 삭제했다 ★

**원인** — `tools/reembed.py` 가 upsert 할 때 이미지 벡터 자리에 `None` 을 넘겼습니다.

```python
vectors.upsert_segments(user_id, video_id, title, segments, text_vectors, None, condition)
```

Qdrant 는 같은 id 로 upsert 하면 **포인트를 통째로 교체**하고, 이름 있는 벡터(named vector)를
부분 갱신하지 않습니다. 글 좌표만 담아 보내면 **그 포인트에서 그림 좌표가 사라집니다.**
에러도 경고도 없고, 이후 검색은 조용히 글 좌표만 쓰게 됩니다.

**수정** — 저장된 프레임에서 그림 좌표를 다시 인코딩해 함께 올립니다. **API 호출은 여전히 0회**입니다.

## 도구 개선 — `tools/why.py`

### `--in` 으로 영상 범위 지정

```powershell
python -m tools.why --list                              # 저장된 영상 목록
python -m tools.why --in 김치찜 "다진마늘 몇 큰술 넣어?"   # 그 영상 안에서만
python -m tools.why "다진마늘 몇 큰술 넣어?"              # 전체에서
```

실제 사용에서는 **어느 영상인지 먼저 정하고 그 안에서 장면을 찾는 것**이 자연스럽습니다.
평가셋도 질문마다 정답 영상이 하나로 정해져 있으므로(`video_id` 컬럼), 전체 검색은
측정 환경과 어긋납니다. 백엔드(`SearchRequest.video_id`, `hybrid_search(video_id=)`)는
**이미 지원하고 있었고**, 쓰는 곳이 없었을 뿐입니다.

### 요약을 반사실(counterfactual)로 교체

기존에는 "그림 좌표가 1등 기여였던 장면: N/M" 을 찍었습니다. **틀린 질문입니다** —
기여도가 낮아도 순위를 뒤집을 수 있고, 높아도 순위를 안 바꿀 수 있습니다.

이제 **그림 좌표를 빼고 다시 정렬해 1위가 바뀌는지**를 출력합니다.
이것이 멘토 자문 2번(각 신호의 필요성 입증)이 요구하는 형태입니다.

## 측정 — SigLIP 이 순위를 바꾼 첫 사례

질의 `"국물이 자작하게 졸아든 장면"`, 범위 `SggDZVu0DPk`

| 구간 | 글 | 그림 | 최종 | 장면 |
|---|---|---|---|---|
| **16~18초** | 0.902 | **1.000** | **0.651** | 다 끓여져 깨 뿌린 완성 상태 |
| 12~16초 | **1.000** | 0.194 | 0.539 | 뚜껑 덮고 끓이기 시작 |

그림 좌표를 빼면 가중치가 재분배되어 **`12~16초`(0.625) 가 `16~18초`(0.564) 를 이깁니다.**

글 좌표가 `12~16초` 에 만점을 준 이유는 자막에 `30분 이상 푹~ 끓여주면 완성` 이 적혀 있어서입니다.
**그건 "앞으로 끓일 것"이지 "졸아든 상태"가 아닙니다.** 그림 좌표가 화면을 보고 바로잡았습니다.

> **한계를 같이 적습니다.** `16~18초` 가 정답이라는 것은 **측정이 아니라 판단**입니다.
> `0~4초` 도 완성된 김치찜 화면입니다. 어느 쪽이 맞는지는 사람이 라벨을 달아야 압니다.
> 사례 1건이므로, 평가셋으로 질의 40~50개에서 세어야 근거가 됩니다.

## 남은 결함 — 고치지 않았습니다

| 항목 | 내용 | 왜 안 고쳤나 |
|---|---|---|
| **질의 분류 실패** | `"몇 큰술"` 이 분량형으로 분류되지 않습니다. `QUANTITY_RE` 가 `\d+\s*(큰술\|...)` 이라 **앞에 숫자를 요구**하는데 `"몇 큰술"` 엔 숫자가 없습니다 | **분류기 교체가 팀의 실험 과제**(RRF / 프로토타입 임베딩 / LLM 중 택일)라 임의로 손대면 그 비교가 흐려집니다. **키워드 방식이 왜 안 되는지의 실증 사례**로 쓰세요 |
| **`minmax` 가 1위를 항상 1.0 으로** | 그림 좌표가 "자신 없음"을 표현할 수 없습니다. 무관한 질의에도 반드시 5개가 나옵니다 | 멘토 자문 3번(관련 장면 없음)의 구조적 원인. `search.py` 설계 변경이라 팀 결정 사항 |
| **질의 번역이 재현되지 않습니다** ★ | 번역 캐시가 프로세스 메모리에 있어, 서버를 껐다 켜면 다시 번역되고 그림 좌표 점수가 달라집니다. 같은 질의에서 `12~16초` 의 그림 점수가 0.000 → 0.194 로 바뀌는 것을 관측했습니다 | **평가 시작 전에 반드시 고쳐야 합니다.** 번역이 흔들리면 개선 때문인지 번역 때문인지 구분할 수 없습니다 |
| **말이 인접 카드에 중복** | Whisper 문장이 8초쯤 되는데 카드는 4초라, 한 문장이 카드 2~3개에 들어갑니다. 인접 카드의 글 좌표가 서로 비슷해져 "몇 초 지점"을 가르기 어렵습니다 | 멘토 자문 1번(의미 단위 병합) 대상. 평가셋으로 전후를 재야 합니다 |
| **EasyOCR 한글 오인식** | `삼경살` `1근술` `35Oml` | 필터로는 못 고칩니다. 프레임 해상도·품질을 올리거나 다른 OCR 을 써야 합니다 |

## 재현 방법

```powershell
# 1. 저장된 영상을 다시 분석 (유튜브 재생 불필요, Gemini 는 장면 설명만)
.venv\Scripts\python.exe -m tools.requeue
.venv\Scripts\python.exe -m uvicorn server.main:app --port 8000

# 2. 진행 상황 (다른 터미널)
.venv\Scripts\python.exe -m tools.requeue --status

# 3. 검색 분해
.venv\Scripts\python.exe -m tools.why --in 김치찜 "국물이 자작하게 졸아든 장면"
```

> `tools.reembed` 와 `tools.requeue` 는 다릅니다.
> **`reembed`** — 임베딩만 다시 겁니다. 글(asr/ocr/caption)은 SQLite 것을 재사용하므로
> Gemini 생성 호출이 0회입니다. 임베딩 모델을 바꿨을 때 씁니다.
> **`requeue`** — 프레임·오디오부터 전 과정을 다시 돌립니다. ASR·OCR·캡션 로직을 고쳤을 때 씁니다.
> 오늘 고친 것은 대부분 분석 단계라 `requeue` 가 필요합니다.
