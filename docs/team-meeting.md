# 팀 회의 자료 — 멘토 자문 반영 현황과 결정할 것

> 2026-09-24 · 작성: 이동현
>
> **회의에서 결정할 것 4가지**가 6장에 있습니다. 시간 없으면 **1장과 6장만** 보셔도 됩니다.

---

## 1. 요약 — 세 줄

1. 멘토 자문(9/18) 5가지 중 **준비가 끝난 건 평가셋 인프라**입니다. 영상 16개 저장 완료,
   라벨링 시트 완성, 질문/라벨링 작업 지침 작성 완료.
2. 남은 건 **사람이 해야 하는 일** — 질문 작성(팀 외부), 정답 라벨링(2인 1조).
   이것만 되면 나머지 개선은 전부 측정하면서 진행할 수 있습니다.
3. 개발 중 **Gemini API 할당량에 세 번 막혔습니다.** 로컬 모델로 옮기는 게 근본 해결인데
   제 노트북 보안 정책에 걸려 보류했습니다 — **6장 결정 사항 ③**.

## 2. 멘토 자문(9/18) 반영 현황

자문 원문과 상세 계획은 [`mentor-feedback.md`](mentor-feedback.md) 에 있습니다.

고쳐서 좋아졌다고 말할 근거가 없으면 의미가 없기 때문입니다.

## 3. 지금까지 한 것

### 영상 16개 저장 완료

목록·링크: [`../eval/video_list.md`](../eval/video_list.md) (노션에 그대로 붙여넣을 수 있습니다)

  색인에는 남겨 검색 난이도를 유지하는 오답 후보로 씁니다.

### 평가셋 인프라

| 산출물 | 내용 |
| --- | --- |
| [`../eval/labeling_sheet.xlsx`](../eval/labeling_sheet.xlsx) | 라벨링 시트. 작성법/라벨링/영상목록/진행현황 4탭. 드롭다운·자동 집계 포함 |
| [`eval-guide.md`](eval-guide.md) | 질문·라벨링 작업 지침. **실제 저장된 영상 내용으로 유형별 예시** |
| `tools/make_labeling_sheet.py` | 시트 생성기. 영상 추가 후 `--force` 로 갱신 |

멘토 지시를 그대로 반영했습니다 — 등급형 라벨(정확 2 / 관련 1 / 무관 0), 질문 유형 3분류,
2인 독립 라벨링, 비대칭 허용 오차(이전 5초·이후 2초), 정답을 **시간(초)** 으로 기록.

마지막 항목이 중요한데, 자문 1번(세그먼트 병합)을 하면 카드 경계가 바뀝니다. 시간으로
적어두면 **평가셋을 다시 안 만들어도** 병합 전후를 같은 잣대로 비교할 수 있습니다.

### 검색 로직 분석

[`search-logic.md`](search-logic.md) — 코드가 실제로 어떻게 도는지 + 하드코딩 12곳.
확인된 문제 중 큰 것 둘:

- **가중치표의 그림 좌표가 기본 설정에서 항상 0**입니다. 실제 적용값은
  speech `(0.62, 0.37, 0)` / visual `(0.75, 0.25, 0)` / lexical `(0.37, 0.62, 0)` —
  **시각 질문일수록 글 좌표 비중이 가장 높아지는 역설**이 생깁니다.
- **min-max 정규화 때문에 각 후보 풀의 1등이 항상 1.0점**이라, 관련 없는 질문에도 결과가
  나옵니다. 자문 3번(관련 장면 없음)을 하려면 이 구조부터 고쳐야 합니다.

### 안정화 (개발 중 터진 것들)

| 문제 | 해결 |
| --- | --- |
| Gemini 무료 티어 하루 20회 — 영상 5개에서 막힘 | 음성을 로컬 faster-whisper 로, 캡션 호출 3회→1회. **영상당 4회 → 1회** |
| ASR·OCR·캡션이 모두 Gemini라 할당량 하나에 전멸 | ASR만 로컬로 빼도 캡션이 429여도 저장은 성공 |
| `gemini-embedding-001` 429 → 저장 전체 실패 | 임베딩 호출에 재시도 추가 (캡션·음성엔 있었는데 여기만 빠져 있었음) |
| `gemini-embedding-2` 가 배치를 1개로 반환 | `types.Content` 로 감싸 해결 + 개수 검증 추가 |
| 임베딩 모델 교체 시 벡터 공간 불일치 | `tools/reembed.py` — 재색인 도구 (Gemini 생성 호출 0회) |

## 4. 앞으로 순서

```
[지금] ─── 질문 작성 (외부) ──┐
                              ├── 라벨링 (2인 1조) ── 합치기 ── 현행 성능 측정
       ─── 평가 스크립트 작성 ┘                                      │
                                                                     ▼
                                            임계값 → 재측정 → 병합 → 재측정 → 가중치 → 재측정
                                                                     │
                                                                     ▼
                                                 정성 평가 10명 · 일정표 · 저작권 문구
```

**평가 스크립트는 질문셋과 병렬로 만들 수 있습니다.** 합성 데이터로 검증해두면 라벨이
도착하는 날 바로 돌릴 수 있습니다.

## 5. 작업 분담 제안

| 작업 | 누가 | 분할 기준 | 예상 |
| --- | --- | --- | --- |
| **질문 작성** | 팀원 4명이 **각자 친구 1명씩** 부탁 | 사람별 | 1인당 30분 |
| **정답 라벨링** | 팀원 **2인 1조 × 2조** | 조별로 질문 절반, 조원은 전부 | 1인당 1.5~2시간 |
| 평가 스크립트 | 1명 | — | |
| 처리 시간·비용 집계 | 1명 | — | 데이터는 이미 있음 |
| 일정표·역할분담표·저작권 문구 | 1명 | — | |

**질문 작성을 한 사람이 몰아서 할 필요 없습니다.** 4명이 각자 친구 1명씩만 부탁해도
4명 × 5개 = 20개가 나오고, **출처가 분산돼서 편향 방지 효과가 오히려 큽니다.**

**라벨링은 "각자 맡은 영상만" 하면 안 됩니다.** 그러면 모든 질문의 라벨러가 1명이라
일치도(κ)를 계산할 수 없고, 그 숫자가 보고서에서 *"우리 평가는 신뢰할 만하다"*의 유일한
근거입니다. 2인 1조로 같은 질문을 각자 라벨링해야 합니다.

## 6. 회의에서 결정할 것 ★

### ① 질문 작성자 섭외 — 누가 누구에게?

각자 1명씩이면 충분합니다. **이번 주 안에** 받아야 다음 단계가 밀리지 않습니다.
목표 45~55개, 유형 3가지가 비슷한 개수.

### ② 라벨링 조 편성

2인 1조 × 2조. 누가 어느 조인지, 언제까지 할지.

### ③ 임베딩을 로컬 BGE-M3로 옮길 것인가 ★ 가장 중요

**문제**: 지금 임베딩은 Gemini API인데 **이틀 사이 두 번 막혔습니다.**
`gemini-embedding-001`이 429로 죽어 `-2`로 옮기고 전체 재색인을 했습니다.
`-2`도 언젠가 같은 일을 당합니다.

**왜 심각한가**: 임베딩 모델을 바꾸면 벡터 공간이 달라져서, **그 전에 측정한 평가 점수가
전부 무효**가 됩니다. 평가 도중에 이 일이 터지면 처음부터 다시 측정해야 합니다.

**로컬 BGE-M3로 가면** API 호출이 0회가 되어 할당량·모델 교체·재현성 문제가 한 번에
해결됩니다. 원래 계획(`담당 D 목표`)이기도 하고, 9/2에 동작 확인도 끝났습니다.

**막힌 이유**: 제 노트북은 **Smart App Control이 켜져 있어** `scipy`/`sklearn`의 컴파일된
파일을 차단합니다. `pip install` 은 되는데 `import` 가 안 됩니다.

| 대안 | 비용 |
| --- | --- |
| **ⓐ 현행 유지** (`gemini-embedding-2`) | 추가 작업 0. API 의존과 재발 위험은 남음 |
| **ⓑ Smart App Control 끄기** | ⚠️ **되돌릴 수 없음** — Windows 초기화해야 다시 켜짐. 관리 기기면 규정 확인 필요 |
| **ⓒ 정책이 꺼진 팀원 노트북에서 색인** | 그 노트북이 색인 담당. Qdrant Cloud 공유 필요(④와 연결) |

> **결정 시한: 평가 측정을 시작하기 전.** 그 전엔 언제 바꿔도 손해가 없고(재색인은
> Gemini 호출 0회), 시작한 뒤엔 바꿀 수 없습니다.

혹시 **Smart App Control이 꺼져 있는 노트북**이 있는지 확인 부탁드립니다. 확인 방법:
Windows 보안 → 앱 및 브라우저 제어 → 스마트 앱 제어 설정.

### ④ Qdrant Cloud를 공유할 것인가

지금은 각자 노트북에 로컬 파일로 돌아서 **저장한 영상이 다른 사람에게 안 보입니다.**
공유 인덱스로 가면:

- 4명이 **각자 다른 영상을 저장해도 하나의 인덱스**로 합쳐집니다
- 각자 자기 Gemini 키를 쓰니 **할당량이 4배**
- 누구나 같은 데이터로 평가를 돌릴 수 있습니다
- ③의 ⓒ안이 가능해집니다

필요한 것: Qdrant Cloud 계정 1개(무료 티어로 충분), 공용 `user_id` 고정, **`.env` 백엔드
설정을 전원 통일**(한 명이라도 다르면 그 인덱스로 잰 숫자는 못 씁니다).

## 7. 부탁 — 일정과 역할

멘토 평가 의견에 이런 문장이 있었습니다:

> 추진 일정과 팀원별 역할 분담은 **제출 자료만으로는 확인이 어려워 해당 항목을 보수적으로
> 평가**하였으며, 최종 보고 시 명시할 것을 권고한다.

**코드 문제가 아니라 문서 누락으로 깎인 항목**이라, 표 두 개만 만들면 회복됩니다.
회의에서 각자 맡은 부분과 실제 진행 날짜를 정리해주시면 제가 문서로 만들겠습니다.
