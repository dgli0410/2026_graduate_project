# "관련 장면 없음" — 구현과 성능 (멘토 자문 3번)

> 근거가 불충분할 경우 답변을 생성하지 않고 '관련 장면 없음'을 안내하는 설계가 필요하다.
> (2026-09-18 서면 자문)

---

## 1. 구현

### 1-1. 순위 점수로는 판정할 수 없습니다

검색은 세 신호를 섞어 순위를 내는데, 섞기 전에 각 신호를 **min-max 정규화**합니다.

```python
def minmax(values):
    lo, hi = min(values), max(values)
    return [(v - lo) / (hi - lo) for v in values]
```

**후보 중 최고가 무조건 1.0이 됩니다.** 실제 유사도와 무관합니다. 그래서 요리 보관함에
`"자동차 엔진 오일 교환하는 장면"`을 물어도 1위 점수가 **1.00**으로 나옵니다(실측).

정규화된 점수는 "후보들 중 몇 등인가"만 말하고 **"애초에 맞는 게 있는가"는 말하지 못합니다.**

### 1-2. 정규화 전 값을 따로 흘려보냅니다

`server/search.py`:

```python
# 글 좌표 검색 결과를 정규화하기 **전에** 원래 코사인 값을 보관
raw_text = {h["segment_id"]: float(h["score"]) for h in text_hits}
...
hit["score_raw"] = round(raw_text.get(seg, 0.0), 4)                # 정규화 전
hit["score"]     = round(w_d*dense + w_l*lexical + w_i*image, 4)   # 정규화 후
```

| 값 | 쓰임 | 성질 |
|---|---|---|
| `score` | 순위 매기기 | 질의마다 1.0으로 재조정. **질의끼리 비교 불가** |
| `score_raw` | **기권 판정** | 원래 코사인. 질의끼리 비교 가능 |

그림 좌표가 아니라 **글 좌표(BGE-M3)의 유사도**를 씁니다. 이 과제에서 가장 믿을 만한
신호이기 때문입니다.

### 1-3. 판정

```python
top_raw = max(s.get("score_raw", 0.0) for s in scenes)
low_confidence = NO_ANSWER_THRESHOLD > 0 and top_raw < NO_ANSWER_THRESHOLD
```

1위 하나가 아니라 **상위 결과 중 최댓값**을 봅니다. 순위가 조금 뒤바뀌어도 판정이
흔들리지 않게 하기 위해서입니다. `NO_ANSWER_THRESHOLD = 0` 이면 기능이 꺼집니다.

### 1-4. 거절이 아니라 경고

결과를 감추지 않고 플래그만 세웁니다. 화면에는 이렇게 뜹니다:

> 저장된 장면 중에 확실히 맞는 것을 찾지 못했습니다. 아래는 그나마 가까운 결과입니다.

두 실수의 무게가 다르기 때문입니다 — **답이 있는데 "없음"이라고 하면 사용자는 영영
못 찾지만**, 답이 없는데 결과를 보여주면 보고 아닌 줄 압니다. 감추면 잘못 걸린 6개를
영영 못 보게 되지만, 경고로 두면 피해가 "불필요한 한 줄"로 끝납니다.

경고가 뜨면 영상 목록도 2개로 좁힙니다. 근거가 약하다고 해놓고 영상을 열 개 늘어놓으면
말과 화면이 어긋나기 때문입니다. 나머지는 "더 보기" 뒤에 남습니다.

## 2. 정답이 없는 질문에 대한 평가

### 2-1. 두 종류를 나눠서 잽니다

| | 예 | 개수 | 출처 |
|---|---|---|---|
| **(가) 분야가 아예 다름** | "자동차 엔진 오일 교환" | 10 | `eval/offtopic.txt` (팀 작성) |
| **(나) 맞는 영상인데 그 장면만 없음** | "맛술은 얼마나 넣어?" | 12 | 평가셋 |

(나)가 훨씬 어렵습니다. 요리 질문이고 요리 영상이라 글이 꽤 비슷하게 맞습니다.
섞어서 하나의 숫자로 보고하면 "어느 쪽을 해결한 것이냐"에 답할 수 없습니다.

> (가)는 팀이 작성했습니다. 평가셋 질문은 외부 지인에게 받았지만 이건 다릅니다 —
> 요리 보관함에 자동차 질문의 답이 없다는 것은 라벨링 판단이 필요 없는 자명한
> 사실이라, 평가셋과 **섞지 않고 따로** 보고합니다.

### 2-2. 임계값 곡선

답 없는 쪽만 보면 반쪽입니다. 그 선에서 **정답이 있는 질문을 몇 개나 잘못 죽이는지**
함께 봐야 합니다. 두 분포를 같이 놓고 임계값을 올리며 셉니다 (`tools/threshold_sweep.py`).

| 임계값 | (가) 올바른 거절 | (나) 올바른 거절 | **잘못된 거절** |
| ---: | ---: | ---: | ---: |
| 0.48 | 8/10 | 2/12 | 3/48 |
| 0.50 | 9/10 | 5/12 | 5/48 |
| **0.52** | **10/10** | **7/12** | **6/48** |
| 0.54 | 10/10 | 9/12 | 8/48 |
| 0.58 | 10/10 | 12/12 | **20/48** |

0.58까지 올리면 거절해야 할 것을 전부 잡지만 **답이 있는 질문의 42%를 같이 버립니다.**

**운영점 0.52** — 분야가 다른 질문은 전부 잡고, 장면만 없는 경우는 58%를 잡으면서,
잘못된 거절이 12.5%입니다.

두 집단의 평균은 **정답 있음 0.587 / 없음 0.509**입니다. 겹칩니다. 어떤 임계값도
깨끗하게 가르지 못하므로, 곡선을 보고 운영점을 고르는 것 외에 방법이 없습니다.

## 3. 한계

- **(나)가 12개뿐입니다.** 7/12의 신뢰구간은 넓습니다. 이 유형의 질문을 더 받아야
  운영점을 더 정확히 고를 수 있습니다
- **`top_raw`는 확률이 아닙니다.** 보정되지 않은 코사인 유사도라 `0.52`에 절대적
  의미가 없습니다. 이론으로 정하지 못하고 곡선을 훑어 고른 이유입니다
- 판단이 **글 좌표 한 신호**에만 기댑니다. 자막·그림이 맞히고 글만 빗나간 경우를
  잘못 거절할 수 있습니다
