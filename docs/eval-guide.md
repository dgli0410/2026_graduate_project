## 0. 왜 하는가 — 30초 설명

지금 검색은 가중치 9개가 **감으로 박혀 있습니다.**

```python
WEIGHTS = {              # (글 좌표, 정확한 단어, 그림 좌표)
    "speech":  (0.5, 0.3, 0.2),
    "visual":  (0.3, 0.1, 0.6),
    "lexical": (0.3, 0.5, 0.2),
}
```

이 숫자를 바꿔서 좋아졌는지 나빠졌는지 **잴 방법이 없습니다.** 평가셋은 그 자를 만드는 일입니다.

멘토 자문 2번이 *"세 신호를 모두 사용했다는 사실보다 각 신호의 필요성을 입증하는 편이
설득력이 높다"* 인데, 입증하려면 자가 있어야 합니다.

## 1. 전체 그림

```
① 질문 만들기        팀 외부인 2~3명   →  45~55개
② 정답 라벨링        팀원 2명 독립     →  같은 질문을 각자
③ 합치기·일치도      자동
④ 측정              자동              →  nDCG, 유형별 성능
```

| | 규모 | 누가 | 시간 |
| --- | --- | --- | --- |
| 대상 영상 | **15개** (16개 중 1개 제외) | — | — |
| 질문 | 영상당 3~4개 = **45~55개** | 팀 외부인 2~3명 | 1인당 30분 |
| 라벨링 | 질문 1개당 2명 | 팀원 2명 | 1인당 1.5~2시간 |

## 2. 질문 만들기 (①)

### 누가 만드나 — 팀원이 아니어야 합니다

멘토 자문:

> 개발팀이 질문과 정답을 모두 작성하면 **시스템이 잘 푸는 질문으로 기울기 쉬우므로**,
> 2인 이상 독립 라벨링 후 일치도를 확인하거나 **질문 작성만이라도 팀 외부에 의뢰**할 것

팀원 4명이 **각자 친구 1명씩** 부탁하면 4명이 모입니다. 한 사람이 여러 명을 섭외할 필요
없습니다. 출처가 분산될수록 편향 방지 효과가 큽니다.

### 부탁할 때 이렇게 말하면 됩니다

> "요리 쇼츠 몇 개 보여줄게. **나중에 이 영상을 다시 볼 때 찾고 싶을 만한 장면**을
> 질문 형태로 5개만 적어줘. 아래 세 종류가 골고루 섞이게."

영상 링크는 [`../eval/video_list.md`](../eval/video_list.md) 에 있습니다.

### 질문 유형 3가지 — 비슷한 개수로

멘토가 지정한 분류입니다. **전체 평균보다 유형 간 차이가 더 유용한 결과**라서 나눠서
측정합니다. 각 유형이 15~18개씩 되게 맞춰주세요.

#### 재료·분량형

무엇을 얼마나 넣는지. 숫자와 단위가 들어갑니다.

| 예시 질문 | 어느 영상 |
| --- | --- |
| 짜장가루 얼마나 넣어? | 짜장 (282ScDPvm28) |
| 국수 몇 그램 삶았어? | 잔치국수 (11C8XqWobjQ) |
| 새우 몇 마리 써? | 새우 계란 피자 (Hwzl8IA9NH0) |
| 고춧가루랑 국간장 몇 스푼씩이야? | 잔치국수 (11C8XqWobjQ) |

#### 순서·타이밍형

언제 무엇을 하는지. "언제", "먼저", "다음에" 같은 말이 들어갑니다.

| 예시 질문 | 어느 영상 |
| --- | --- |
| 마늘은 언제 넣어? | 짜장 (282ScDPvm28) |
| 언제 뒤집어? | 새우 계란 피자 (Hwzl8IA9NH0) |
| 치즈는 언제 올려? | 새우 계란 피자 (Hwzl8IA9NH0) |
| 양파보다 고기를 먼저 볶아? | 짜장 (282ScDPvm28) |

#### 시각적 상태형

**말로 설명 안 되고 화면을 봐야 아는 것.** 색, 모양, 질감, 정도.

| 예시 질문 | 어느 영상 |
| --- | --- |
| 고기를 어느 정도까지 볶아? | 짜장 (282ScDPvm28) |
| 마늘이 어떻게 되면 계란물 부어? | 새우 계란 피자 (Hwzl8IA9NH0) |
| 애호박은 얼마나 얇게 썰어? | 잔치국수 (11C8XqWobjQ) |
| 짜장 소스 다 됐을 때 어떤 상태야? | 짜장 (282ScDPvm28) |

> 이 유형이 **프로젝트의 핵심**입니다. 멘토가 *"'색이 갈색이 될 때까지'처럼 시각 정보에만
> 존재하는 단서도 있다"* 고 한 게 이겁니다. 음성·자막만으로는 못 찾고 장면 설명이 있어야
> 찾히는 질문이라, 신호별 기여도를 가르는 지점입니다.

### ★ 답이 없는 질문을 5~8개 섞으세요

전체의 10~15%는 **영상에 답이 아예 없는 질문**으로 만듭니다.

| 예시 | 왜 답이 없나 |
| --- | --- |
| (짜장 영상에) 설탕 얼마나 넣어? | 설탕이 안 나옴 |
| (잔치국수에) 계란 고명 어떻게 만들어? | 계란이 안 나옴 |
| (새우 피자에) 오븐 몇 도에 구워? | 팬으로만 함 |

**이유**: 멘토 자문 3번이 *"근거가 불충분할 경우 답변을 생성하지 않고 '관련 장면 없음'을
안내하는 설계가 필요하다"* 인데, 모든 질문에 답이 있으면 그 기능을 시험할 방법이 없습니다.
지금 시스템은 항상 1등을 내놓게 돼 있어서 이 질문들에서 전부 틀릴 텐데, **그게 바로
"그래서 임계값을 도입했다"의 근거**가 됩니다.

## 3. 정답 라벨링 (②)

### 한 줄 정의

> **"이 질문의 답은 이 영상 몇 초에서 몇 초 사이에 나온다"를 사람이 직접 보고 적는 것.**

우리 검색 결과는 **절대 보지 않습니다.** 시스템과 무관하게 정답을 먼저 확정해야, 나중에
시스템을 고쳐도 같은 잣대로 비교할 수 있습니다.

### 절차

**① 영상을 `watch` 주소로 엽니다**

쇼츠 페이지는 타임라인이 제대로 안 보입니다. 주소를 바꿔서 여세요:
```
youtube.com/shorts/282ScDPvm28   →   youtube.com/watch?v=282ScDPvm28
```
`,` / `.` = 한 프레임씩, `j` / `l` = 10초씩, `k` = 일시정지.
([`../eval/video_list.md`](../eval/video_list.md) 의 링크는 이미 watch 주소입니다)

**② 질문을 읽고, 답이 나오는 순간을 찾습니다**

**③ 시트에 적습니다** — [`../eval/labeling_sheet.xlsx`](../eval/labeling_sheet.xlsx) [라벨링] 탭

### 실제 예시 3가지

#### 예시 A — 재료·분량형

질문: **"짜장가루 얼마나 넣어?"** (282ScDPvm28)

영상 20~24초에 자막 `양파 1개 짜장가루 1.5큰술 넣어줘요` 가 뜨고 말로도 *"짜장가루 있죠?
하나, 반 정도"* 라고 합니다.

| qid | video_id | question | q_type | start | end | grade |
| --- | --- | --- | --- | --- | --- | --- |
| q01 | 282ScDPvm28 | 짜장가루 얼마나 넣어? | 재료분량 | 20.0 | 24.0 | 2 |

#### 예시 B — 순서·타이밍형 (정답 구간이 2개)

질문: **"마늘은 언제 넣어?"** (282ScDPvm28)

8~12초에 *"여기에 마늘도 같이 볶아줍니다"* — 이게 답입니다(2점).
4~8초는 그 직전에 돼지고기를 넣는 장면인데, 답은 아니지만 순서를 이해하는 데 도움이
됩니다(1점).

| qid | video_id | question | q_type | start | end | grade |
| --- | --- | --- | --- | --- | --- | --- |
| q02 | 282ScDPvm28 | 마늘은 언제 넣어? | 순서타이밍 | 8.0 | 12.0 | 2 |
| q02 | 282ScDPvm28 | 마늘은 언제 넣어? | 순서타이밍 | 4.0 | 8.0 | 1 |

> **한 질문이 여러 줄**이 됩니다. `qid`·`question`·`q_type`·`video_id` 는 똑같이 반복합니다.

#### 예시 C — 답이 없는 질문

질문: **"설탕 얼마나 넣어?"** (282ScDPvm28 — 설탕이 안 나옴)

| qid | video_id | question | q_type | start | end | grade |
| --- | --- | --- | --- | --- | --- | --- |
| q03 | 282ScDPvm28 | 설탕 얼마나 넣어? | 재료분량 | | | 없음 |

`start`·`end` 를 비우고 `grade` 에 `없음` 만 적습니다. **한 줄이면 됩니다.**

### 등급 기준

| 등급 | 기준 |
| --- | --- |
| **2 · 정확** | 이 구간만 봐도 답을 알 수 있다. "이거 하나만 보여줘도 만족한다" 수준일 때만 |
| **1 · 관련** | 답은 아니지만 맥락상 도움이 된다. 준비 동작, 재료 소개, 직후 결과 |
| **0 · 무관** | 나머지 전부. **시트에 적지 않으면 자동으로 0점** |
| **없음** | 그 질문의 답이 영상에 존재하지 않는다 |

### 판단이 갈릴 때 4가지 규칙

1. **구간 경계** — 답이 보이거나 들리기 시작하는 순간부터 끝나는 순간까지. **최소 2초**
2. **애매하면 2 대신 1.** 2점은 확실할 때만
3. **정답 구간이 여러 개면 전부** 적는다 (간장을 두 번 넣으면 두 줄)
4. **시간은 소수점 첫째 자리** (22.0, 26.5)

### ⚠ 말과 자막이 다를 때

실제로 이런 경우가 있습니다. 짜장 영상 12~20초 구간:

```
12~16초  자막: "간장 1큰술"
16~20초  말  : "여기에 간장 소스도 2T"
```

**둘 다 적으세요.** 어느 쪽이 맞는지 판단하지 말고, 둘 다 답의 근거가 되는 구간이니
각각 한 줄씩 넣으면 됩니다. 이런 불일치 자체가 "음성과 자막 중 어느 신호가 더 믿을
만한가"를 재는 재료가 됩니다.

### 2명 독립 라벨링 — 꼭 이렇게

**각자 맡은 영상만 라벨링하면 안 됩니다.** 그러면 모든 질문의 라벨러가 1명이라 일치도를
계산할 수 없습니다. 2인 1조로 묶으세요:

| 조 | 담당 질문 | 라벨러 |
| --- | --- | --- |
| 1조 | q01 ~ q25 | **A, B 각자 전부** |
| 2조 | q26 ~ q50 | **C, D 각자 전부** |

- 한 사람이 라벨링하는 양은 **25개** — 나눠 하는 것과 비슷합니다
- 모든 질문에 라벨러가 2명 → 일치도(κ) 계산 가능
- **누가 저장한 영상인지는 상관없습니다**

**서로 상의하지 마세요.** 이게 "독립"의 전부입니다. 다 하면 각자 파일을 그대로 제출하면
되고, 합치기·일치도 계산·불일치 항목 추출은 자동으로 합니다. 여러분은 불일치 목록만 보고
합의하시면 됩니다.

### 흔한 실수 3가지

- ❌ **우리 시스템 검색 결과를 보고 라벨링** → 평가가 무의미해집니다
- ❌ **세그먼트 번호로 적기** → 반드시 **시간(초)**. 나중에 4초 카드를 의미 단위로 병합해도
  평가셋을 다시 안 만들어도 되기 때문입니다 (멘토 자문 1)
- ❌ **두 사람이 같이 앉아서** → 독립성이 깨져 일치도가 의미를 잃습니다

## 5. 다 되면 무엇이 나오나

평가 스크립트를 돌리면 이런 표가 나옵니다:

```
                nDCG@5   Recall@5   질문 수
전체              0.68      0.74        50
  재료분량        0.81      0.88        17
  순서타이밍      0.72      0.76        16
  시각적상태      0.51      0.59        17     ← 약한 지점
기준선 A (제목)   0.31      0.35        50
기준선 B (ASR만)  0.55      0.61        50
```

"시각적상태가 0.51"이 나오면 그게 곧 **"시각 신호 가중치를 올려야 한다"는 데이터 근거**
입니다. 감으로 정하던 걸 숫자로 정하는 게 이 작업의 목적입니다.

그리고 개선할 때마다 다시 재서 최종적으로 이 표를 만듭니다:

| 단계 | nDCG@5 | 변화 |
| --- | --- | --- |
| 기준선 — 제목·설명 검색 | 0.31 | — |
| 기준선 — ASR 단일 신호 | 0.55 | |
| 현행 시스템 | 0.68 | |
| + 절대 임계값 (자문 3) | ? | |
| + 세그먼트 의미 병합 (자문 1) | ? | |
| + 가중치 재설계 (자문 2) | ? | |

**이 표가 졸업작품의 핵심 결과물입니다.**
