## 1. `.env` 의 빈 값 뒤 주석이 값으로 읽힌다 ★

**증상** — 모든 영상이 분석 중 실패.

```
ValueError: Can't find 'adapter_config.json' at '# 요리 도메인 LoRA. 측정 결과 이득이 없어 비워 둡니다'
```

**원인** — `.env.example` 의 이 줄입니다.

```
SIGLIP_ADAPTER=             # 요리 도메인 LoRA. 측정 결과 이득이 없어 비워 둡니다
```

**값이 비어 있는 줄에 인라인 주석이 붙으면 `python-dotenv` 가 주석 전체를 값으로 읽습니다.**
SigLIP 이 `'# 요리 도메인 LoRA...'` 라는 이름의 폴더에서 LoRA 를 찾다가 죽습니다.

값이 **있는** 줄(`OCR_BACKEND=easyocr   # easyocr | gemini`)은 주석이 정상적으로 떨어집니다.
빈 값일 때만 터지므로, 그 항목을 쓰지 않는 사람은 평생 못 봅니다.

**수정** — 주석을 윗줄로 옮겼습니다. `.env.example` 전체를 훑어 같은 패턴을 모두 고쳤습니다.

> **이미 `.env` 를 만들어 둔 사람은 본인 파일도 고쳐야 합니다.** `.env` 는 저장소에 없어서
> `.env.example` 만 고쳐서는 전파되지 않습니다.

## 2. Qdrant 창고가 768차원 그대로 남았다

**증상** — 좌표 저장 단계에서 전부 실패.

```
ValueError: could not broadcast input array from shape (1024,) into shape (768,)
```

**원인** — 글 좌표를 Gemini(768) 에서 BGE-M3(1024) 로 바꾸면 창고를 새로 만들어야 합니다.
`client.delete_collection()` 을 불렀는데 **`meta.json` 만 1024 로 바뀌고 실제 저장 파일
(`storage.sqlite`)은 768짜리 그대로 남았습니다.**

로컬 Qdrant 는 파일 모드로 돌고 **닫을 때 디스크에 반영**합니다. 삭제를 돌린 스크립트가
종료되며 `Exception ignored ... deallocator` 로 깨졌고, 반영이 반만 됐습니다.

**수정** — 폴더째 지웠습니다. 프로세스 상태에 기대지 않는 방식이라 확실합니다.

```powershell
# 서버를 먼저 끈 뒤
rm -rf data/qdrant
python -m tools.requeue
```

> 장면 카드의 글은 `data/vault.db` 에 있으므로 창고를 지워도 잃는 것은 없습니다.
> 서버가 켜질 때 지금 설정의 차원으로 새로 만듭니다.

## 3. EasyOCR 이 한글 경로에서 모든 프레임을 실패한다 ★★

**증상** — `analysis_health` 에 이렇게 찍힙니다.

```json
"ocr": {"status": "ok_empty", "failed_frames": 38,
        "partial_error": {"error_type": "AttributeError",
                          "message": "'NoneType' object has no attribute 'shape'"}}
```

**원인** — `_reader.readtext(str(path))` 로 **경로 문자열**을 넘기면 EasyOCR 이 내부에서
`cv2.imread` 를 씁니다. **OpenCV 는 윈도우에서 한글이 든 경로를 열지 못하고 `None` 을
돌려줍니다.** 그 `None` 에서 `.shape` 를 읽다가 터집니다.

실측:

```
상대 경로  data\media\...\00000459.jpg                    -> ndarray   정상
절대 경로  C:\...\일학습병행_광운대_이동현\...\00000459.jpg   -> None      실패
```

서버는 절대 경로를 쓰고 이 저장소 폴더 이름에 한글이 있어, **모든 프레임이 실패**했습니다.

**왜 못 알아챘나** — 영상은 `ready` 로 끝나고 자막 칸도 채워져 있었습니다. OCR 이 비면
**Gemini 격자 호출이 읽은 글자가 대신 들어가기** 때문입니다(`segmenter` 의 폴백).
겉보기로는 완전히 정상이고, EasyOCR 이 한 글자도 읽지 못했다는 사실은 `failed_frames`
에만 남습니다.

**수정** — 파일을 직접 디코딩해 배열로 넘깁니다. 경로 인코딩과 무관해집니다.

```python
data = np.fromfile(str(path), dtype=np.uint8)   # 경로 인코딩을 타지 않습니다
image = cv2.imdecode(data, cv2.IMREAD_COLOR)
return cv2.cvtColor(image, cv2.COLOR_BGR2RGB)   # EasyOCR 은 RGB 를 기대합니다
```

**효과**

| | 수정 전 | 수정 후 |
|---|---|---|
| OCR 단계 결과 | 18개 중 `ok` **0개** | 18개 중 `ok` **18개** |
| 자막이 들어간 장면 | (전부 Gemini 폴백) | **190/203 (94%)** |

## 5. 첫 성능 측정

```
python -m tools.eval_search --all --out eval/result_<날짜>.json
```

평가셋 질문 60개(측정 48 + 정답 없음 12). 설계는 [`eval-guide.md`](eval-guide.md) 참고.

| | nDCG@5 | Recall@5 | 1위적중 |
|---|---:|---:|---:|
| **10-09 — Gemini 전 구간, 버그 있음** | **0.775** | 0.833 | 0.729 |
| **10-10 — 로컬 모델, 버그 수정, 캡션 55%** | **0.751** | 0.812 | 0.708 |

**이 둘을 그대로 비교하면 안 됩니다.** 10-10 색인에는 **장면 설명이 5개 영상에서 빠져
있습니다**(설명 100% → 55%). 그 5개에 평가 질문이 20개 붙어 있어, 신호 하나가 통째로
빠진 상태의 값입니다. 캡션을 채운 뒤 다시 재야 로컬 전환의 효과를 말할 수 있습니다.

### 유형별 — 세 번 측정에서 순서가 유지됩니다

| 유형 | 10-09 (33문항) | 10-09 (48문항) | 10-10 (48문항) |
|---|---:|---:|---:|
| **시각적상태** | 0.921 | 0.843 | **0.839** |
| 순서타이밍 | 0.790 | 0.750 | 0.735 |
| **재료분량** | 0.794 | 0.748 | **0.703** |

표본과 색인이 바뀌어도 **시각적상태가 가장 높고 재료분량이 가장 낮습니다.** 세 번 모두
같은 순서라 우연으로 보기 어렵습니다.

재료분량이 이번에 가장 많이 떨어진 것(-0.045)은 **OCR 엔진이 바뀐 영향**일 수 있습니다.
수량 질문은 자막 의존도가 높은데, EasyOCR 의 한글 오인식(`1큰술` → `1근술`, `350ml` →
`35Oml`)이 기록에 남아 있습니다. 단어 매칭에서 `1큰술` 질의가 `1근술` 자막에 걸리지
않습니다. 캡션을 채운 뒤 재측정해 확인해야 합니다.

### 아직 쓸 수 없는 것

| 항목 | 상태 |
|---|---|
| **기준선 A (제목·설명)** | 10-09 에는 현행과 소수점까지 동일했습니다. 영상 **안에서만** 검색하면 제목이 모든 카드에 같아 재정렬이 일어나지 않습니다. 10-10 에 +0.009 로 갈라졌지만 여전히 기준선 구실을 못 합니다. 빼거나 "어느 영상인지 찾기"(전체 검색)로 바꿔야 합니다 |
| **라벨러 일치도(κ)** | 계산 불가. 담당을 **영상별**로 나눠 같은 질문을 두 사람이 라벨링한 경우가 0건입니다. 질문을 팀 외부에 의뢰했으므로 멘토 자문 5번의 **"또는"** 조건은 충족합니다 |
| **자문 3번 (관련 장면 없음)** | 정답 없는 질문 12개에서 **12개 모두 결과를 내놓습니다**(평균 1위 점수 0.71). `minmax` 정규화가 1등을 항상 1.0 으로 만들기 때문입니다. 임계값 도입 전후를 비교할 기준선이 생겼습니다 |
