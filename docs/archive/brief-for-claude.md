# 졸업작품 검색 시스템 평가셋 설계 — 배경과 현황

나는 대학 졸업작품으로 **유튜브 쇼츠 장면 검색 시스템**을 만들고 있다.
지금 **평가셋(정답 데이터)을 만드는 단계**이고, 그 설계가 타당한지 검토받고 싶다.

## 1. 시스템이 무엇을 하는가

유튜브 쇼츠를 "저장"하면, 크롬 확장이 영상을 재생하면서 **0.5초마다 화면을 캡처**하고
**오디오를 녹음**해서 서버로 보낸다. 서버는 이걸 분석해 **4초 단위 "장면 카드"** 로 쪼갠다.

장면 카드 하나는 이렇게 생겼다:

```json
{
  "segment_id": "282ScDPvm28_seg_002",
  "start_time": 8.0,
  "end_time": 12.0,
  "asr_text": "여기에 마늘도 같이 볶아줍니다",        // 음성 인식 (Whisper)
  "ocr_text": "기름이 충분히 나오도록 볶아줘요",       // 화면 자막 (OCR)
  "caption": "팬에 돼지고기를 넣은 모습입니다...",     // 장면 설명 (Gemini)
  "frame_path": "frames/00009955.jpg"
}
```

나중에 **"마늘은 언제 넣어?"** 라고 자연어로 물으면, 관련 장면을 찾아 **그 초로 영상을
이동**시켜 준다. 요리 쇼츠 도메인으로 범위를 좁혔다.

현재 영상 15개, 장면 카드 143개가 저장돼 있다.

## 2. 검색이 어떻게 동작하는가 (평가 대상)

질문이 들어오면 **세 가지 신호**를 가중합해서 장면을 정렬한다.

| 신호 | 무엇 | 어떻게 |
| --- | --- | --- |
| **dense** (글 좌표) | 의미가 비슷한가 | 장면 카드 텍스트와 질문을 임베딩해 코사인 유사도 |
| **lexical** (정확한 단어) | 그 단어가 실제로 들어 있나 | 질문 토큰 중 본문에 포함된 비율 (BM25 아님, 단순 부분문자열) |
| **image** (그림 좌표) | 그림이 비슷한가 | 프레임을 SigLIP2로 임베딩 (현재 꺼져 있음) |

가중치는 질문 성격에 따라 바뀌는데, **9개 숫자가 전부 사람이 감으로 써 둔 상수**다:

```python
WEIGHTS = {                  # (dense, lexical, image)
    "speech":  (0.5, 0.3, 0.2),   # "감자 언제 넣어?"
    "visual":  (0.3, 0.1, 0.6),   # "빨간 냄비 나오는 장면"
    "lexical": (0.3, 0.5, 0.2),   # "300g", "2큰술"
}
```

질문 성격 분류도 규칙 기반이다 — 숫자+단위 정규식이 걸리면 `lexical`, 시각 단어 사전
15개 중 하나가 있으면 `visual`, 나머지는 `speech`. **단 하나만 고르고**, `if` 순서가 곧
우선순위라 `"빨간 냄비에 간장 2큰술"` 은 숫자가 먼저 걸려 시각 정보가 무시된다.

**아는 문제점이 몇 가지 더 있다:**

1. 기본 설정에서 그림 좌표가 꺼져 있어서 그 몫이 나머지 둘에 비례 배분된다.
   실제 적용값은 speech `(0.62, 0.37, 0)` / visual `(0.75, 0.25, 0)` /
   lexical `(0.37, 0.62, 0)` — **시각 질문일수록 글 좌표 비중이 가장 높아지는 역설**.
2. 점수를 min-max 정규화해서 **각 후보 풀의 1등이 항상 1.0점**이 된다. 절대 유사도가
   얼마든 상위 결과가 나오므로 **"관련 장면 없음"을 판단할 수 없다.**
3. dense/image는 상대 정규화된 값인데 lexical은 절대 비율이라 **스케일이 다른 수를
   그냥 더하고 있다.**

**평가셋의 목적은 이 가중치와 개선안을 감이 아니라 숫자로 정하는 것이다.**

## 3. 멘토 자문 (2026-09-18, 서면)

중간평가에서 현업 전문가(통신사 차장)에게 받은 자문이다. 평가 설계 지시가 구체적이다.

### 보완 요구 5가지

1. **장면 분할 단위** — 4초 고정 분할은 '재료를 볶는다', '불을 줄인다' 같은 의미 단위와
   경계가 어긋나 하나의 행위가 여러 조각으로 흩어진다. 고정 분할을 **기준선으로 두고**,
   인접 세그먼트를 의미 단위로 병합하는 후처리를 추가할 것.
2. **신호별 역할 규명** — 숏폼은 나레이션과 화면 자막이 중복되는 경우가 많고, 반대로
   '색이 갈색이 될 때까지'처럼 **시각 정보에만 존재하는 단서**도 있다. 질문 유형별로
   어떤 신호가 유효한지 정리하면 **그 자체가 본 프로젝트의 핵심 기여**가 된다.
   세 신호를 모두 사용했다는 사실보다 **각 신호의 필요성을 입증**하는 편이 설득력이 높다.
3. **근거의 신뢰성** — RAG 구조를 표방하는 이상 제시한 타임스탬프와 실제 장면이 일치해야
   하며, 한 번 어긋나면 사용자 신뢰가 즉시 훼손된다. **근거가 불충분할 경우 답변을 생성하지
   않고 '관련 장면 없음'을 안내**하는 설계가 필요하다.
4. **처리 비용·지연** — 영상 1건당 처리 시간과 비용을 실측해 자료에 명시할 것.
5. **저작권·이용약관** — 현재 범위(개인 학습·연구 목적)를 발표 자료에 명시할 것.

### 평가 방법 지시 7가지

> 하나의 질의에 정답 장면이 복수일 수 있다는 지적은 타당하나, 이는 정보검색 분야에서 이미
> 다루는 문제이므로 **정성 평가로 이동하기 전에 정량 설계를 먼저 보완**할 것.

1. 정답을 이진 판정이 아닌 **등급(정확 2 / 관련 1 / 무관 0)** 으로 라벨링하고
   **nDCG를 주지표**로 사용할 것. Recall@K와 mAP는 정답 집합을 복수로 확장해 산출.
2. 시점 정확도는 **비대칭 허용 오차**(예: 이전 5초, 이후 2초 이내)를 적용할 것.
   사용자는 목표 장면보다 **앞서 시작하는 것은 감수하지만 지나쳐 시작하는 것은 감수하지
   못한다.**
3. **질문 유형별**(재료·분량 / 순서·타이밍 / 시각적 상태)로 성능을 분리해 보고할 것.
   전체 평균 하나보다 **유형 간 성능 차이가 더 유용한 결과**다.
4. **비교 기준선**을 설정할 것. 제목·설명 기반 검색, 음성 인식 단일 신호 대비 개선폭을
   제시하는 편이 절대 수치보다 설득력이 높다.
5. **평가셋 편향에 유의**할 것. 개발팀이 질문과 정답을 모두 작성하면 시스템이 잘 푸는
   질문으로 기울기 쉬우므로, **2인 이상 독립 라벨링 후 일치도를 확인**하거나
   **질문 작성만이라도 팀 외부에 의뢰**할 것.
6. 정성 평가는 병행하되 소규모로 충분하다. 10명 내외에게 특정 장면 탐색 과제를 부여하고
   **과제 성공률과 소요 시간**을 측정하는 방식이 만족도 설문보다 신뢰도가 높다.

# 우리가 설계한 평가셋

## 4. 규모

| | 개수 | 누가 | 예상 시간 |
| --- | --- | --- | --- |
| 저장 영상 | **15개** | (완료) | — |
| 질문 대상 영상 | **14개** (1개는 캡처가 끊겨 제외) | — | — |
| 질문 | 영상당 3~4개 = **45~55개** | **팀 외부인 2~3명** | 1인당 30분 |
| 라벨링 | 질문 1개당 **2명 독립** | 팀원 2인 1조 × 2조 | 1인당 1.5~2시간 |

질문을 안 만든 영상도 **검색 대상에는 남겨둔다**(오답 후보 역할). 검색은 15개 전체에서
돌기 때문에 난이도는 유지되면서 라벨링 부담만 줄어든다.

## 5. 데이터 형식

엑셀 시트 한 장. 컬럼 9개. **한 행 = 정답 구간 하나** (질문 하나가 아님).

| 컬럼 | 내용 | 누가 채우나 |
| --- | --- | --- |
| `qid` | 질문 번호 (q01, q02…). 같은 질문의 여러 행은 같은 qid | 질문 단계 |
| `video_id` | 유튜브 영상 ID | 질문 단계 |
| `question` | 질문 문장 | 질문 단계 |
| `q_type` | `재료분량` / `순서타이밍` / `시각적상태` | 질문 단계 (팀이 분류) |
| `start` | 정답 구간 시작 (초, 소수점 1자리) | 라벨링 단계 |
| `end` | 정답 구간 끝 (초) | 라벨링 단계 |
| `grade` | `2`(정확) / `1`(관련) / `없음`(영상에 답이 없음) | 라벨링 단계 |
| `labeler` | 라벨러 이름 | 라벨링 단계 |
| `note` | (선택) 메모 | 라벨링 단계 |

**0점(무관)은 적지 않는다** — 시트에 없는 구간은 자동으로 0점.

### 설계 의도 두 가지

**① 정답을 세그먼트 번호가 아니라 시간(초)으로 적는다.**
멘토 자문 1번(인접 세그먼트 의미 단위 병합)을 적용하면 장면 카드의 경계가 바뀐다.
시간으로 적어두면 **평가셋을 다시 만들지 않고** 병합 전후를 같은 잣대로 비교할 수 있다.

**② 질문 단계와 라벨링 단계를 같은 행에서 나눠 채운다.**
질문 4칸을 먼저 채운 시트를 **2부 복사**해서 라벨러 두 명에게 각각 준다. 라벨링을 시작한
뒤에 복사하면 한쪽 라벨이 다른 쪽에 보여 독립성이 깨진다.

## 6. 작업 순서

```
① 외부인에게 질문 받기 (형식 자유, 카톡·메모)
      ↓
② 팀이 시트에 옮기며 qid 부여 + q_type 분류
      ↓
③ ★ 여기서 시트를 2부 복사 (질문만 채워진 상태)
      ↓
④ 라벨러 2명이 각자 start/end/grade 채움 (서로 상의 금지)
      ↓
⑤ 두 파일 합치기 → 일치도(κ) 계산 → 불일치 항목만 합의
      ↓
⑥ 측정 — nDCG, 유형별 분리, 기준선 대비 개선폭
```

### ① 외부인에게 부탁하는 말

> "요리 쇼츠 5개 보여줄게. **나중에 이 영상을 다시 볼 때 찾고 싶을 만한 장면**을
> 질문 형태로 5개만 적어줘. 아래 세 종류가 골고루 섞이게."

엑셀을 주지 않는다. `qid`, `q_type` 같은 걸 채우라고 하면 부담만 커진다.
팀원 4명이 각자 친구 1명씩 부탁하면 4명이 모이고, **출처가 분산돼 편향 방지 효과가 크다.**

## 7. 질문 유형 3가지와 실제 예시

예시는 전부 **실제로 저장된 영상의 실제 내용**이다.

### 재료·분량형 — 무엇을 얼마나

| 질문 | 근거 |
| --- | --- |
| 짜장가루 얼마나 넣어? | 20~24초 자막 "양파 1개 짜장가루 1.5큰술 넣어줘요" |
| 국수 몇 그램 삶았어? | 32~36초 자막 "국수 120g 250원어치 삶았습니다" |
| 새우 몇 마리 써? | 8~12초 음성 "오늘의 주인공 새우 10마리도" |

### 순서·타이밍형 — 언제 무엇을

| 질문 | 근거 |
| --- | --- |
| 마늘은 언제 넣어? | 8~12초 음성 "여기에 마늘도 같이 볶아줍니다" |
| 언제 뒤집어? | 16~20초 자막 "손목 스냅으로 뒤집어주고" |
| 치즈는 언제 올려? | 20~24초 "토마토소스 2스푼이랑 치즈 뿌려서" |

### 시각적 상태형 — 화면을 봐야 아는 것 ★ 핵심

| 질문 | 근거 |
| --- | --- |
| 고기를 어느 정도까지 볶아? | 12~16초 자막 "기름이 충분히 나오도록 볶아줘요" + 장면 설명 "노릇하게 볶고 있습니다" |
| 마늘이 어떻게 되면 계란물 부어? | 12~16초 자막 "마늘이 노릇해지면 팬에 그대로" |
| 애호박은 얼마나 얇게 썰어? | 8~12초 장면 설명 "채칼로 애호박을 길고 얇게 채 썰고 있습니다" |

이 유형이 멘토가 말한 *"시각 정보에만 존재하는 단서"* 에 해당한다. 음성·자막만으로는 못
찾고 장면 설명이 있어야 찾히는 질문이라, **신호별 기여도를 가르는 지점**이다.

### 답이 없는 질문 — 전체의 10~15% (5~8개)

| 질문 | 왜 답이 없나 |
| --- | --- |
| (짜장 영상에) 설탕 얼마나 넣어? | 설탕이 안 나옴 |
| (잔치국수에) 계란 고명 어떻게 만들어? | 계란이 안 나옴 |
| (새우 피자에) 오븐 몇 도에 구워? | 팬으로만 함 |

**이유**: 멘토 자문 3번("근거가 불충분하면 '관련 장면 없음'을 안내")을 시험하려면 답이 없는
질문이 있어야 한다. 현재 시스템은 min-max 정규화 때문에 항상 1등을 내놓으므로 이 질문들에서
전부 틀릴 것이고, **그게 "그래서 임계값을 도입했다"의 근거**가 된다.

## 8. 라벨링 규칙

### 한 줄 정의

> **"이 질문의 답은 이 영상 몇 초에서 몇 초 사이에 나온다"를 사람이 직접 영상을 보고 적는 것.**

우리 시스템의 검색 결과는 **절대 보지 않는다.** 시스템과 무관하게 정답을 먼저 확정해야
나중에 시스템을 고쳐도 같은 잣대로 비교할 수 있다.

### 등급

| 등급 | 기준 |
| --- | --- |
| **2 · 정확** | 이 구간만 봐도 답을 알 수 있다. "이거 하나만 보여줘도 만족한다" 수준일 때만 |
| **1 · 관련** | 답은 아니지만 맥락상 도움이 된다. 준비 동작, 재료 소개, 직후 결과 |
| **0 · 무관** | 나머지 전부. 시트에 적지 않으면 자동으로 0점 |
| **없음** | 그 질문의 답이 영상에 존재하지 않는다 |

### 판단이 갈릴 때 4가지 규칙

1. **구간 경계** — 답이 보이거나 들리기 시작하는 순간부터 끝나는 순간까지. 최소 2초
2. **애매하면 2 대신 1.** 2점은 확실할 때만
3. **정답 구간이 여러 개면 전부** 적는다 (간장을 두 번 넣으면 두 줄)
4. **시간은 소수점 첫째 자리** (22.0, 26.5)

### 입력 예시

한 질문에 정답 구간이 2개인 경우:

| qid | video_id | question | q_type | start | end | grade | labeler |
| --- | --- | --- | --- | --- | --- | --- | --- |
| q02 | 282ScDPvm28 | 마늘은 언제 넣어? | 순서타이밍 | 8.0 | 12.0 | **2** | 준서 |
| q02 | 282ScDPvm28 | 마늘은 언제 넣어? | 순서타이밍 | 4.0 | 8.0 | **1** | 준서 |

답이 없는 경우 (한 줄, start·end 비움):

| qid | video_id | question | q_type | start | end | grade | labeler |
| --- | --- | --- | --- | --- | --- | --- | --- |
| q03 | 282ScDPvm28 | 설탕 얼마나 넣어? | 재료분량 | | | **없음** | 준서 |

### 실제로 부딪힌 애매한 사례

짜장 영상 12~20초 구간에서 **자막과 음성이 어긋난다**:

```
12~16초  자막: "간장 1큰술"
16~20초  음성: "여기에 간장 소스도 2T"
```

우리 방침: **둘 다 적는다.** 어느 쪽이 맞는지 라벨러가 판단하지 않는다. 이런 불일치 자체가
"음성과 자막 중 어느 신호가 더 믿을 만한가"를 재는 재료가 되기 때문이다.

### 2인 독립 라벨링

**각자 맡은 영상만 라벨링하면 안 된다.** 그러면 모든 질문의 라벨러가 1명이라 일치도를
계산할 수 없다. 2인 1조로 묶는다:

| 조 | 담당 질문 | 라벨러 |
| --- | --- | --- |
| 1조 | q01 ~ q25 | A, B가 **각자 전부** |
| 2조 | q26 ~ q50 | C, D가 **각자 전부** |

한 사람이 라벨링하는 양은 25개로 나눠 하는 것과 비슷한데, 모든 질문에 라벨러가 2명이 된다.

## 9. 측정 설계

### 비대칭 허용 오차

시스템이 안내한 시작 시각 `s`, 정답 구간 `[g_start, g_end]` 에 대해:

```
g_start - 5.0  ≤  s  ≤  g_start + 2.0     → 그 구간의 등급을 인정
```

멘토의 *"앞서 시작하는 것은 감수하지만 지나쳐 시작하는 것은 감수하지 못한다"* 를 구현한 것.
현재 시스템은 찾은 지점보다 1.5초 일찍 이동시키므로 이 기준 안에 들어온다.

### 지표

- **주지표: nDCG@5** (등급형 라벨 2/1/0과 세트)
- 보조: Recall@5, mAP (정답 집합 복수 확장)
- **유형별로 분리해서 보고** (전체 평균보다 유형 간 차이가 중요)
- 라벨러 일치도 (Cohen's κ)

### 기준선 2종

| | 내용 |
| --- | --- |
| A | 영상 제목·설명 텍스트만으로 검색 (장면 검색 없이) |
| B | ASR(음성 인식) 신호 하나만 사용 |

절대 수치보다 **기준선 대비 개선폭**을 제시한다.

### 최종 산출물

| 단계 | nDCG@5 | 변화 |
| --- | --- | --- |
| 기준선 A — 제목·설명 검색 | ? | — |

# 10. 물어보고 싶은 것

위 설계에 대해 아래를 검토해 달라. (필요한 것만 골라 물어도 된다)

### 평가 설계의 타당성

1. 질문 45~55개 / 영상 14개 규모로 **nDCG가 안정적으로 나오는가?** 유형별로 나누면
   유형당 15~18개인데, 이 표본으로 "유형 간 성능 차이"를 말해도 되는가?
   통계적으로 유의하다고 하려면 몇 개가 필요한가?
2. **등급을 2/1/0 세 단계로만** 두는 게 적절한가? 더 세분화하거나 단순화할 이유가 있나?
3. 비대칭 허용 오차 **이전 5초 / 이후 2초**가 합리적인가? 쇼츠(15~60초)는 일반 영상보다
   짧은데 더 좁혀야 하나?
4. **기준선 2종**이 충분한가? 더 두면 좋을 기준선이 있나?

### 라벨링 품질

5. **"애매하면 2 대신 1"** 규칙이 라벨 분포를 왜곡하지 않나? 2점이 너무 적어지면
   nDCG가 불안정해지지 않나?
6. 자막과 음성이 어긋날 때 **둘 다 적는** 방침이 맞나? 라벨러 일치도를 떨어뜨리지 않나?
7. **Cohen's κ** 를 쓰려면 라벨을 어떤 단위로 맞춰야 하나? 우리는 "시간 구간"으로
   적는데, 두 사람이 적은 구간이 **부분적으로만 겹칠 때** 일치/불일치를 어떻게 판정하나?
8. 일치도가 얼마 이상이면 "신뢰할 만하다"고 말할 수 있나?

### 편향

9. 질문을 외부인이 만들어도, **우리가 고른 영상 15개** 안에서 만드는 것이라 영상 선택
   편향은 남는다. 이걸 줄이거나 최소한 보고하는 방법이 있나?
10. 답이 없는 질문을 **전체의 10~15%** 로 잡았는데 적절한가?

### 측정 방법

11. nDCG 계산에서 **정답이 아예 없는 질문**(grade=없음)은 어떻게 처리해야 하나?
    이상적 순위(IDCG)가 0이라 정의가 안 되는데, 별도 지표로 빼야 하나?
12. 한 질문의 정답 구간이 여러 개일 때 **nDCG의 gain을 어떻게 매기나?** 상위 5개에
    같은 정답 구간을 가리키는 결과가 2개 들어오면 중복으로 점수를 줘야 하나?
13. 개선을 단계적으로 쌓아가며(임계값 → 병합 → 가중치) 측정하는데, 이렇게 하면
    **각 개선의 기여를 분리할 수 없지 않나?** ablation을 따로 해야 하나?
